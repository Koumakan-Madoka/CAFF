### 2026-11-05 本机 Git 快照采集（v2）

新轮次采用 best-effort Git 快照，不再使用下面 v1 历史采集契约的原生读取、目录 pin、防替换或多次扫描校验；不是安全沙箱，也不保证原子一致性。旧格式封存及其回放逻辑保留。新格式的恢复/回放接线另行实现；当前旧恢复入口对 v2 明确报 `git_snapshot_requires_head_materialization`，不能把仅恢复 overlay 当成完整现场。

- 项目页的 `POST /api/projects/:id/badcase-capture/configure` 开关以已登记项目路径为根，`targetDir` 可省略，若提供必须与项目路径相同。Git 自行解释普通仓库和 `.git` 文件 worktree；本轮实际 cwd 必须为仓库顶层，且与项目根的 `git common dir` 相同。新建 worktree 无需登记或重开。关闭不检查/扫描源目录，已有封存不删除。旧 authorize/estimate/enable 管理入口暂留兼容，但新开关及新轮次不使用这些原生路径。
- 开启前的 `estimateGitDirectoryAsync` 复用采集器，只做内存预览，不安装 helper、不 pin、不写检查点/CAS。返回 `fileCount`（HEAD 普通文件数加本次未跟踪文件数）、`totalBytes`（本次去重的补丁/overlay/skill 字节，不含 HEAD 基线、session、manifest）、`skippedCount/uncaptured`。`complete:false` 表示存在缺口，不阻止开启；只有预览失败/`captureAvailable:false` 才拒绝。读取页面本身不启动预览。
- 只读 Git 查询 HEAD/分支/common dir、`diff --binary HEAD`（暂存、未暂存、删除的合并效果）及 `ls-files --others --exclude-standard -z`。为逐项隔离异常，先取变更路径，再按路径取 binary diff 拼接；禁用外部 diff/textconv。设置 `GIT_OPTIONAL_LOCKS=0`，不刷新/修改源 index、状态、文件或 refs。未跟踪文件遵循 Git ignore；默认排除 `.git`、`node_modules`。不支持 submodule、嵌套仓库、非 Git 目录；不保留暂存/未暂存的区分。
- 单文件 10 MiB，单次未跟踪合计 200 MiB。链接/junction、保留/非法名、读失败、长路径、超限等逐项跳过，`uncaptured/skipped` 和 `stats.skippedCount` 记录原因；不跟随链接，不把缺口称为完整现场。非仓库或无法读取 HEAD 不生成检查点；采集失败不阻塞正常 turn。只对本机已知 key 原值作 `[*]` 替换，不使用旧秘密哨兵；为避免替换破坏 patch，命中已知值的 tracked 改动改存完整脱敏 overlay 或删除记录。
- 检查点 `schemaVersion:2`、`gitSnapshot.kind:"git-snapshot-v1"`；`gitSnapshot` 含 `sourceRepository/commonDir/head/branch/patchBlobHash/patchBytes/baseFileCount/untrackedBytes/excludedPatterns/projectSkills`。补丁和普通文件均复用项目 CAS；`files` 是未跟踪/脱敏 tracked overlay，不是完整工作树。`deletions` 记录已知删除；`projectSkills[]` 以 `originalPath` 和相对路径 `files` 归档 skill 及资源，纳入保留引用闭包。当前来源为 SDK 显式 skill 路径及 cwd 默认 skill 根，实际加载清单尚须补齐，不声称已覆盖所有 SDK 发现路径。
- 采集库必须在项目目录之外；部署前由操作方显式设置外置 `CAFF_BADCASE_CAPTURE_DIR` 并按正常发布流程重启。此说明不是移动现有库、修改生产配置或部署的授权。v2 当前尚未完成真实实例/旧新回放验收，不能沿用下面 v1 的历史验收结论。

- 仅在项目显式开启采集后工作。`projects.html` 正常入口为选择工作目录和开关；读取页面不自动授权、开启或扫描内容。管理请求沿用 loopback/Host/Origin/CSRF 门禁，信任同一 OS 用户，不是人类身份认证或抵御同权限进程的沙箱。
- `agent-executor.ts` 在本轮 prompt、实际 SDK cwd 和 session 选择确定后、`startRun` 前保存检查点。范围是该 turn 实际 worktree，不根据可能陈旧的 Room 路径猜测，也不是每次工具调用前快照。关闭后不再主动采集，既有封存不删除。
- 保存纳入范围的已跟踪文件、脏内容、未跟踪文件及删除/缺席状态；遵循显式排除、内存秘密占位替换和 ignored 纳入策略。Git 分类元数据不作为恢复出的 `.git`，私有/凭据目录不能因“整个 worktree”被纳入。内容按 SHA-256 存 CAS，清单引用内容；恢复仅写入专属新空目录，不修改真实仓库，不从 HEAD 补回已删除文件。
- 保存归一化 prompt、执行配置、声明的角色片段及可用的执行前 session。resume 缺少 session 不得退回 fresh。采集失败或材料缺失不伪造检查点、完整性或可回放状态；正常 turn 与采集成功不是同一事实。
- Windows helper 升级不需要重新授权：使用前按当前可信源码 SHA-256 幂等安装到采集库内 `windows-authorization-helper/windows_read.<SHA>.py`，仅以 `wx` 创建缺失的当前版本，写后及每次使用前校验 SHA。已存在且校验通过则直接复用；校验失败拒绝，不修复或覆盖当前文件，不覆盖其他 SHA，不更改项目授权、开启状态或 pin。并发安装观察到未写完的文件时本次失败关闭，后续轮次可重新校验；安装仍计入原有采集时限。
- Windows 枚举到保留名（如 `NUL`、`nul.txt`、`CON`、`AUX`、`COM1–9`、`LPT1–9`）、尾随点/空格或非法字符名时，跳过该条目，不打开、不读取、不递归；其余文件继续预估/采集。纳入范围内的这些名字（即使被 Git ignore）进入 `uncaptured`，原因固定为 `windows_reserved_or_invalid_name`；预估返回 `skippedCount`，文件数/字节数仅统计可采部分。显式排除和私有目录仍先裁剪，不枚举其内部。预估 `complete:true` 仅表示有界枚举/分类已结束，可携带这些明确缺口，不代表现场可完整恢复；检查点保存同一缺口、`stats.skippedCount` 和 `files_uncaptured` 材料缺失原因，不绕过恢复/回放准入。跳过项仍计入枚举上限并参与多次扫描的名字一致性核对，不推断其下文件已删除。直接路径/选择器校验、非法原生目录记录、pin、reparse 防护、非便携 Git index 拒绝和 25 秒总时限不放宽。
- Windows 枚举工作树时，通过已持有的父目录句柄读取 `FILE_DIRECTORY_INFORMATION` 属性；遇到任何 `FILE_ATTRIBUTE_REPARSE_POINT`（junction、目录/文件符号链接、悬空链接或其他 tag）都在子条目打开之前跳过，不打开链接本身、不读目标、不跟随、不递归、不删除源链接。范围内条目记为 `uncaptured`，原因固定为 `reparse_point_skipped`，和非法名字缺口共同计入预估 `skippedCount`、检查点 `stats.skippedCount` 及原枚举上限。明确缺口参与跨扫描一致性核对，不计入可恢复文件/字节，也不作为该路径或子树的删除证据；检查点带 `files_uncaptured`，不得声称现场完整，恢复时这些路径及目标内容均不存在，不重建链接。显式排除/私有目录仍优先裁剪；`complete:true` 仍只表示有界预估已结束而非现场完整。授权根、直接读取路径和祖先中的 reparse 继续拒绝，目录 pin、`OBJ_DONT_REPARSE`/打开后属性检查不变；普通条目在枚举后被替换为 reparse 时失败关闭，不把其他打开错误冒充可跳过项。25 秒总时限和恢复/回放门禁不放宽。
- Windows 主路径使用已有原生采集实现。2026-11-03 起不再要求服务/agent 全局设置 `GIT_CONFIG_*`：采集只解析独立授权的 index/config/ignore 字节，不运行git、不读系统/用户Git配置。每次原生Python helper启动都复制当时环境，去掉全部大小写拼写的 `GIT_*`，仅在该子进程设置 `GIT_CONFIG_NOSYSTEM=1/GIT_CONFIG_GLOBAL=NUL/GIT_TERMINAL_PROMPT=0`；不写回process.env或任何Git配置文件，普通agent的Git选择器/用户配置保持原样。这只是采集配置隔离，不是通用子进程或秘密沙箱。
- Windows异步管理预估总是先走相同授权/私有根边界的Git分类预检，是否可开启不再取决于服务启动或运行时的Git环境。分类成功且完整才有 `captureAvailable:true`；分类不支持时仍可给出只读原始容量，保留分类失败原因和 `git_classification_unavailable`，强制 `captureAvailable:false`，不把容量扫描当采集许可。分类与容量预览共享同一个25秒单调时钟截止点，失败后不另获25秒预算；超时不给部分成功。原有显式授权、pin、估算凭据和单独enable不变；采集每轮仍重验实际元数据。新检查点以 `git_configuration_isolated_in_capture_helpers` 说明隔离，不再声称宿主全局配置已禁用；旧封存记录不改。不同平台的读取实现不能互相充当验证证据。
- 容量是逻辑落盘字节，不是物理分配块/空闲空间保证。UI 区分最近检查点新增文件、session、其他回放内容、共享 CAS、清单成本；缺少旧统计时显示未知，镜像成本不在其中。检查点发布前耗时不等于整个 turn 耗时。
- 清单/blob 自洽不证明原子现场；并发写入一致性、权限和 Git 元数据保真不在本 MVP 承诺内，`strictEvalEligible` 不升级为 true。

### 用户标记与封存

- 用户在聊天 UI 选择一条终态 assistant 消息，填写“实际问题”和“期望行为”，确认后保存标记并尝试封存其执行前现场。UI 不要求用户填写检查点 ID、JSON 或再做一次封存确认。
- 关联由服务端从消息的 project/conversation/message/turn/agent/task/checkpoint/run 派生，不接受客户端改绑。标记与封存状态分别查询；已标记不代表已封存，已封存不代表可回放。
- 同一消息相同文本重复提交幂等，不新增第二份封存；不同文本不覆盖原记录。没有执行前检查点的旧消息显示缺现场，材料缺失不现场补造。进程重启后，对仍存在且归属有效的消息可查询原记录。
- 封存通过保留引用 pin 住清单和可达 blob，不受普通期限/配额回收。采集存储在源 worktree 外，属于同 OS 用户可信存储，不挂载给评测 agent。
- 标记成功后才尝试附带的 Wiki 入库；来源消息缺失、入库错误或存储位于项目内等不支持布局均返回 `wikiCase.error: wiki_case_unavailable`，不隐藏已保存的标记或阻断封存。Wiki 存储布局在使用时按当前项目列表校验；不支持时 Wiki API 仍拒绝、零 Wiki 写入，但不令整个聊天服务启动失败。消息摘录按导入的32 KiB UTF-8边界截断并如实保存截断标记。

### WikiSkill 用例、模型归纳与审核

- `scripts/badcase-capture/import-text-cases.cjs --config <绝对路径> --confirmed` 是操作方入口，不部署到 3100。新全局配置含 `globalRoot`（实例的 `<agentDir>/badcase-global`）、`sourceWorktree`（仅用于校验存储在源目录外）、`selections`；不含所属 `projectId`。旧项目配置只为迁移/历史入口兼容保留。每项 selection 仅含用户确认的 `conversationId`、`messageId`、`actual`、`expected`。没有确认参数时不访问 API、不落盘。
